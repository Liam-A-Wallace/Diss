# Developer Guide — "Seeing the Fake" (Diss/)

An orientation for getting productive in this codebase without reading every
file. Start here, then jump to the section for whatever you're changing.

---

## 1. What this project is

A **PsychoPy experiment** for "Study 1": participants classify face
images as **REAL** or **FAKE** (AI-generated) and rate their confidence on a
1–5 scale, while a webcam eye-tracker (GazeFollower) records their gaze.

The high-level pipeline is a **three-stage loop**, repeated per trial:

```
ready cross  →  face image (self-paced view)  →  REAL/FAKE click  →  confidence click  →  ITI
```

Around it sit a calibration/preview step, instruction screens, a practice
trial, a mid-session break, and crash-safe checkpointing.

There are **two adjacent concerns** that live in sibling folders and are *not*
part of this repo's runtime code, but matter to the whole:

- **`../Dataset/`** — the raw image corpora (~23 GB, kept outside git) that the
  curation toolchain reads/writes. Referenced via the `RAW_DATA_ROOT` env var.
- **`../GazeFollower/`** — the third-party eye-tracking SDK, imported as a
  **pristine, unmodified** checkout (we override behaviour via `gaze.py` and
  `gazefollower_patch.py` rather than editing it).

## 2. The mental model

**Runtime is a thin orchestration layer over three subsystems:**

| Subsystem | Files | Responsibility |
|-----------|-------|----------------|
| **Experiment** (main loop) | `experiment.py` | Window setup, trial loop, screen flow, data saving |
| **Eye tracking** | `gaze.py`, `gazefollower_patch.py`, `overlay.py` | Wrap GazeFollower, sample continuously, trim to image windows |
| **Stimulus curation** | `dataset/`, `stimulus-curation/` | Turn raw corpora → picked/curated images → `stimuli/` + `trials.csv` |

**The key architectural subtlety:** gaze is **always sampling** once the
session starts. Each trial's face "window" is stamped with a flip-accurate
`onset_ns`/`offset_ns` (epoch nanoseconds, the same clock GazeFollower uses),
and the continuous stream is trimmed to those windows only when the session
ends. This is what makes the gaze-per-trial data exact — see §5.

Every design decision in this repo is a trade-off that's commented at the
point of use. When in doubt, **read the comments in the files** — they are
unusually good and explain *why*, not just *what*.

## 4. How a single trial actually runs

Follow `run_trial()` in [`experiment.py`](../experiment.py) while reading this:

1. **Load & pre-scale the image** *before* the fixation cross, so nothing
   loads between fixation and stimulus onset (avoids a dropped-frame jitter).
2. **Ready cross** (`screens.run_ready`, via `overlay` + `gaze`): blocks until
   the tracker has *fresh* calibrated gaze near the cross. If the gaze has
   drifted, the first ENTER shows a recalibrate prompt; `R` recalibrates.
3. **Face view:** image drawn with the "ENTER/SPACE to continue" hint. Onset is
   stamped via `win.callOnFlip(...)` on the first flip; offset on the flip that
   removes the image — so the recorded window is *exactly* what was on screen.
4. **Classification** (`screens.wait_for_click`): left/right REAL vs FAKE
   buttons; reaction time measured from the first flip of the screen.
5. **Confidence** (same helper): 1–5 buttons with "Guessing"/"Very sure"
   captions.
6. **ITI** then return a dict of per-trial results, added to the
   PsychoPy `ExperimentHandler`/`TrialHandler`.

**Control-flow patterns to know:**
- `QuitExperiment` (ESC anywhere) and `RecalibrateRequest` (R) are raised from
  deep inside screen loops and caught at well-defined points
  (`_show_info`, `_run_trial_with_recal`) to either abort cleanly or
  recalibrate-and-retry.
- ESC **always saves** data collected so far — shutdown is wrapped so no single
  step can abort the rest (`finally:` block in `main`).

## 5. Eye-tracking data flow (the part most people trip on)

GazeFollower samples continuously and reports calibrated gaze in **its own
screen's pixel space** (`(0,0)` = top-left, +y down). The experiment's clock is
the same epoch-ns clock.

1. `gaze.start_sampling()` begins a session-wide continuous stream.
2. Every trial records a `window` (onset/offset ns) via
   `gaze.record_window(...)`.
3. On shutdown, `stop_session()` writes **three** gaze files:
   - `*_gaze_raw.csv` — every sample of the session;
   - `*_windows.csv` — per-trial onset/offset sidecar;
   - `*_gaze.csv` — raw stream **trimmed to image windows** (via
     `trim_gaze_file`), with added `trial`, `is_practice`, `condition`,
     `t_rel_ms`.
4. **Crash recovery**: `windows.csv` + `gaze_raw.csv` can rebuild the trimmed
   file after a crash (`gaze.trim_gaze_file`).

**Coordinate-space caveat** (see [`overlay.py`](../overlay.py)): GazeFollower's
pixel space ≠ PsychoPy's `pix` units. `overlay.py` normalises by the tracker's
resolution and remaps into the window. If you ever combine gaze coordinates
with PsychoPy coordinates, do the same normalisation — the two "screen sizes"
are independent and can differ.

**Quality flags:** each trial records `gaze_samples`, `gaze_valid_frac`,
`dropped_frames`, and `drift_px`. Low-valid trials are only *logged*, not
excluded — filtering is a post-processing decision.

## 6. Configuration cheat sheet ([`config.py`](../config.py))

The knobs you're most likely to reach for:

| Setting | Meaning |
|---------|---------|
| `GAZE_MODEL` | Gaze model filename (default `"base_32M.mnn"`). `""` = GazeFollower default. |
| `CALIBRATION_POINTS` | 5 / 9 / 13-point calibration. |
| `GAZE_FILTER` | `"one_euro"` (adaptive) or `"heuristic"`. |
| `LOCK_CAMERA_EXPOSURE`, `CAMERA_EXPOSURE` | Fix exposure so bright/dark stimuli don't bias gaze. |
| `BREAK_AT_FRACTION` | Insert rest break after this fraction of trials. |
| `CHECKPOINT_EVERY` | Save progress every N trials. |
| `GAZE_MIN_VALID_FRAC` | Below this valid-gaze fraction a trial is logged low-quality. |
| `GAZE_READY_WINDOW` / `FACE_LOST_AFTER` | Ready-cross gating thresholds. |
| `DRIFT_WARN_PX` | Gaze distance from cross that triggers the recalibrate prompt. |
| `PRACTICE_TRIALS`, `PRACTICE_CSV` | Practice setup. |
| `TRIALS_CSV`, `PLACEHOLDER_CSV` | Which trial list to load. |
| `WIN_SIZE`, `FULLSCREEN`, `SCREEN` | Window/display config. |
| `STIM_HEIGHT`, `IMAGE_POS` | How the face is displayed (PsychoPy `height` units). |

## 7. Running & common workflows

```powershell
python experiment.py                          # real stimulus list (trials.csv)
python experiment.py --placeholder            # generated placeholder stimuli
python experiment.py --demo                   # live gaze dot overlay
python experiment.py --test                   # write to data/test/ (not participant data)
python experiment.py --demo --placeholder     # combine flags
```

**Keyboard:** ENTER/SPACE = advance · `R` = recalibrate · ESC = quit-and-save.

**Add/change participant-facing text** → edit [`texts.py`](../texts.py), not
`screens.py`.

**Change a layout, colour, or timing** → edit [`config.py`](../config.py) first;
most values are already exposed there.

**Add a button/text element** → use `ui.text` / `ui.Button` / `ui.rounded_rect`.

**Regenerate the stimulus set** (see `dataset/README.md`):
```powershell
python dataset\scripts\review.py --per-label 25     # pick images
python dataset\scripts\export_to_diss.py            # → stimuli/ + trials.csv
```

**Headless pipeline check** (no camera/window needed):
```powershell
python dataset\scripts\smoke_test.py
```

## 8. Gotchas & invariants

- **Don't edit `../GazeFollower/`.** Override behaviour in `gaze.py` /
  `gazefollower_patch.py` instead. (`git status` there should stay clean.)
- **`GAZE_MODEL` selects the model at runtime** — it is *not* done by swapping
  model files. Passing it through `MGazeNetGazeEstimator` keeps the checkout
  pristine.
- **Raw corpora live outside this repo** (`../Dataset/datasets/`). Use the
  `RAW_DATA_ROOT` env var if you relocate them; all curation scripts honour it.
- **Image load timing matters** — images are pre-loaded before the fixation
  cross to avoid a dropped frame at onset. Don't reorder that.
- **ESC must always save** — keep shutdown steps in independent `try/except`s.
- **Participant IDs are filename-sanitised** (`screens._safe_id`) because they
  become part of output filenames.
- **`data/` and `stimuli/` are gitignored** — participant data and downloaded
  media must never be committed.
- **GazeFollower's pixel space ≠ PsychoPy pix** — always normalise when mixing
  the two (see §5).
