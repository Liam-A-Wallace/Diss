# Files to review for possible removal

This review is based on code references and the documented workflows, rather
than file age alone. No candidate listed here has been deleted. Paths are
relative to `Diss`. Unreferenced scripts can still be useful when run manually.

## Regenerable clutter

| Candidate | Why it is a candidate | What removal would mean |
| --- | --- | --- |
| `__pycache__/` and Python caches inside source folders | Compiled Python cache, already ignored by Git | Python recreates these on import. No source code is lost. |
| `trials_placeholder.csv` | Generated by `tools/make_placeholders.py`; `experiment.py --placeholder` regenerates it | Keep the generator while the `--placeholder` option exists. This CSV is not the main `trials.csv`. |
| `processed/demo_preview/` | Static preview of five photos created during demo setup | Removes only this viewing page. The photos remain in `stimuli/demo/`. |
| `processed/demo_landmarks/` if present | Preview images and landmark CSV created by `python -m tools.demo_landmarks` | Can be regenerated from the selected images and local landmark model; retain any exported results you need. |
| Repeated numbered reports in `processed/` | Rerunning analysis preserves earlier reports in new folders | Compare parameters and keep the reports you need before removing duplicates. Never infer that different session folders are duplicates. |

## Legacy or overlapping tools: decide before removing

| Candidate | Evidence | Condition to check |
| --- | --- | --- |
| `dataset/scripts/curate.py` | The dataset guide labels it the legacy Easy/Medium/Hard six-cell workflow; current selection uses `review.py` and `export_to_diss.py` | Remove only if abandoning that design. `dataset/scripts/smoke_test.py` imports `curate`, so update or retire that check together. |
| `stimulus-curation/build_manifest.py` | Overlaps with `dataset/scripts/build_60k_manifest.py`; both build DFR60K manifests | They are not identical and write to different default folders. Choose one supported workflow and update the enrichment guide before retiring the other. |
| `stimulus-curation/curated.csv` | Historical 30-image sample with derived difficulty/cell columns; documented as not an input to `enrich.py` | Preserve if needed to trace earlier selections or results. Current demo uses `dataset/outputs/picked.csv`. |
| `stimulus-curation/common.py` | Overlaps with `dataset/scripts/common.py`, but hashes differ | Not independently removable: `stimulus-curation/enrich.py` imports its local `common`. Consolidation requires code and path changes. |
| `tools/make_placeholders.py` and the placeholder option | Cartoon faces are unnecessary for the real-photo pilot | Still imported by `experiment.py --placeholder`; retire the option, its config and guide references together if no longer wanted. |

The whole `stimulus-curation/` folder is optional to running the experiment,
but it includes useful photo/face/demographic enrichment code. There is not
enough evidence to label the entire folder useless.

## Keep as source material or active dependencies

- `data/`: original gaze, responses, timing sidecars and session metadata.
  Older sessions may lack the sidecars required by the current pipeline; this
  does not make the raw recordings disposable.
- `stimuli/` and `trials.csv`: images and trial lists. Existing sessions identify
  images by hashes; moving or replacing images can prevent reconstruction.
- `aois/`: masks, manual edits and saved review hashes. Regenerating a model mask
  does not restore a human correction or review.
- `dataset/outputs/picked.csv`: selected-image provenance and the demo's source
  manifest. Review logs and source metadata can also be research provenance.
- `models/`: downloadable, but deletion forces another download (about 339 MB
  for the face-parsing weights). It is not needed to display stimuli, but it is
  needed for offline AOI generation.
- `.venv/`, `.git/`, `tests/`, and the experiment's root Python modules: installed
  dependencies, history, regression checks and actively referenced runtime code.
- `image_view.py` and `viewing.py`: complementary, not duplicates. The former
  handles geometry/gaze mapping; the latter runs the image-viewing interaction.
- `dataset/scripts/common.py` and the enrichment helper: support manual tools
  even though they are not imported by `experiment.py`.

## Organisation changes made

- `DEMO.md` -> `docs/DEMO.md`
- `DEV_GUIDE.md` -> `docs/DEV_GUIDE.md`
- Previous full root guide preserved as `docs/EXPERIMENT.md`; the root README is
  now a shorter index of commands and folders.
- `demo_landmarks.py` -> `tools/demo_landmarks.py`. New command:
  `python -m tools.demo_landmarks` from `Diss`.
- `make_placeholders.py` -> `tools/make_placeholders.py`; the experiment import
  was updated. Standalone command: `python -m tools.make_placeholders`.

The commands `python experiment.py`, `python demo.py`, and `python analyse.py`
remain the everyday entry points. Requirement files remain at the root so setup
commands are easy to find.
